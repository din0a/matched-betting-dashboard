Matching safeguards: The engine requires matching race ID, runner ID, market type, racing code and country. It rejects unverified names-only matches, missing timestamps, stale prices, scratched runners, races already started, closed markets and unknown/insufficient Betfair lay liquidity. The scanner only compares WIN with WIN; PLACE markets are excluded. Confirm settlement terms, market status and current executable odds before using a result. "Alternative bookmaker" two-way Dutching is not a valid substitute for a Betfair lay in multi-runner racing.

Data-feed format and realistic live setup

Upload one row per quoted runner. Required: race_id,runner_id,race_type,country,market,runner,bookmaker,side,odds,observed_at,start_time. Betfair lay rows must use bookmaker=Betfair and side=LAY. Bookmaker rows use side=BACK. Add available to Betfair rows for available lay stake at the quoted price, plus status and scratched. Times must be ISO-8601 with timezone (UTC Z is easiest). Identifiers must come from a trustworthy event and runner mapping; don't fabricate shared IDs based on name similarity.

Your GitHub Pages site can poll a CORS-enabled HTTPS endpoint but cannot securely store bookmaker/Betfair API credentials. Deploy the optional private feed-proxy backend supplied in the website package and connect an authorised provider that produces this schema. International and per-bookmaker coverage must be verified with that provider. The app does not place bets.

Supported bookmaker directory

Bet Right, bet365, BetDeluxe, BetNation, Chalk24, Dabble, GoldBet, Ladbrokes, mybet, Neds, OKEBET, Palmerbet, Picklebet, PointsBet, Punt123, RealBookie, RobWaterhouse, Sportsbet, TAB, TABtouch, topbet, UltraBet, Unibet. Excluded as requested: MintBet, BearBet and ReadyBet. Fantasy-sports apps and the generic Sports folder are also excluded. A listed bookmaker is a filter option, not proof of a connected live feed.

Feed connection status

Not connected to live Betfair or bookmaker APIs. You can import matched rows or use an authorised HTTPS feed. A local HTML file cannot safely hold Betfair login credentials or bypass bookmaker restrictions. For real cross-bookmaker scanning, a server-side adapter must identify identical events, markets, outcomes, start times and settlement rules.

Automatic odds scanner

Offline scanner: import a CSV or load fictional examples. Live scanning requires a separately configured authorised HTTPS JSON feed. The scanner recalculates imported matches and can poll that feed while this page is open.

JSON feed: array of objects or {"markets":[...]}; same column names as CSV. One row represents one comparable back/lay selection, not necessarily an entire event. For bookmaker-versus-bookmaker two-outcome hedges, set exchange to the opposite bookmaker, lay to opposite odds, and hedge_mode to opposite. This requires a verified two-outcome market. Browser CORS restrictions and provider API terms apply. A feed must already provide matched back/lay selections: this page does not scrape bookmaker sites or independently match market identifiers. Feed URL is not stored or sent anywhere other than the URL you enter.
